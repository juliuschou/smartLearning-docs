# 智學互動平台 - 題目領域契約

> [!important] 單一語意來源
> 本檔是 [[智學互動平台]] Web 與 CLI／Agent 建題的共用 domain contract，也是 P0-04 的現行規範。原始 [[需求蒐集#題目需求層概念 schema|題目需求層概念 schema]] 保留作為來源；若有不一致，以本檔為準。

## 目的與邊界

本契約統一以下入口的題目語意與 validation：

- 老師在 Web 建立、編輯、刪除及排序單一題目。
- Web 批次建立題目。
- CLI／Agent 批次 validation、預覽、確認與建立題目。
- LiveSession 啟用時建立 SessionQuestion 快照。

本契約定義 domain object、欄位語意、驗證規則及 error/warning 分類；實際 JSON wire format、endpoint、資料表、ORM mapping、schema migration 與 framework implementation 留待 M2。

> [!note] 驗收勾選語意
> 本檔 `[x]` 代表需求內容已確認,不代表功能已實作或測試通過。

## Domain object

### QuestionDefinition

QuestionDefinition 是 Course 中可編輯、可跨 LiveSession 重用的題目定義。

| 欄位語意 | 必要性 | 規則 |
|---|---|---|
| Question ID | 平台建立後必要 | 不可變，由平台指定；Web/CLI 均不得自訂正式 ID |
| Type | 必要 | `poll`、`open_text`、`quiz` |
| Prompt | 必要 | Unicode 純文字；trim 後 1～1,000 字元 |
| Selection mode | 依題型 | `single` 或 `multiple`；只適用 `poll` |
| Options | 依題型 | `poll`／`quiz` 必要；`open_text` 禁止 |
| Correct option refs | 依題型 | `quiz` 必要；`poll`／`open_text` 禁止 |
| Source | 平台 metadata | `web` 或 `cli` 等可驗證來源；不改變題目能力 |
| Order | Course 內必要 | 表示題庫顯示順序；具體儲存方式留 M2 |

### SessionQuestion

SessionQuestion 是 LiveSession 從 `waiting` 進入 `active` 時，由 QuestionDefinition 建立的不可變快照。

包含：

- 來源 Question ID，供追蹤但不形成即時依賴。
- 當時的題型、題幹、選項、正確答案與場次順序。
- 該場逐題狀態：`not_open → open → closed`。
- 該場 Submission 與結果關聯。

規則：

- 快照後修改或刪除 QuestionDefinition，不影響進行中或歷史 LiveSession。
- 同一 QuestionDefinition 可在不同 LiveSession 產生不同快照版本。
- SessionQuestion 在同一 LiveSession closed 後不可重開。
- MVP 不允許 LiveSession active 後新增、刪除、改內容或重新排序 SessionQuestion。

### Option

| 欄位語意 | 規則 |
|---|---|
| Option ref | 在單一 QuestionDefinition 內唯一；批次輸入可由 client 指定暫時 ref，正式儲存 ID 由平台決定 |
| Text | Unicode 純文字；trim 後 1～250 字元 |
| Order | 題目內穩定顯示順序 |

第一版不支援 Markdown、HTML、附件、圖片或其他 rich content。

## 題型規則

### Poll

| 欄位 | 規則 |
|---|---|
| `type` | `poll` |
| `prompt` | 必要 |
| `selection_mode` | 必要，`single` 或 `multiple` |
| `options` | 必要，2～10 個 |
| `correct_option_refs` | 禁止 |

- `single` Submission 必須且只能選一個 option。
- `multiple` Submission 至少選一個 option，不得重複選同一 option，最多不能超過題目 option 數量。
- Poll 不判定正確答案。

### Open text

| 欄位 | 規則 |
|---|---|
| `type` | `open_text` |
| `prompt` | 必要 |
| `selection_mode` | 禁止 |
| `options` | 禁止 |
| `correct_option_refs` | 禁止 |

- Submission 為 Unicode 純文字，trim 後 1～2,000 字元。
- 第一版不接受 HTML、Markdown、附件或 rich content。
- 題型在 UI 顯示為「問答」，domain type 固定為 `open_text`，避免 API 與 UI 名稱分裂。

### Quiz

| 欄位 | 規則 |
|---|---|
| `type` | `quiz` |
| `prompt` | 必要 |
| `selection_mode` | 禁止；由正確答案數量推導單選／複選 |
| `options` | 必要，2～10 個 |
| `correct_option_refs` | 必要，至少一個，且每個 ref 都須存在於 `options` |

- 一個 correct option 表示單選測驗；多個 correct options 表示複選測驗。
- 單選 Submission 必須且只能選一個 option。
- 複選 Submission 至少選一個 option，不得重複選同一 option。
- 複選答案集合須與正確答案集合完全相同才算正確。
- 第一版不提供部分得分、加權計分或文字語意評分。

## 共用 validation

### 正規化與阻擋錯誤

- 題幹與 option text 先去除前後空白，再檢查空值及長度。
- 重複 option 以 Unicode 正規化、trim、合併連續空白及忽略大小寫後判斷。
- 正規化後重複 option 是阻擋建立或更新的 error。
- 不得包含不符合該題型的欄位；例如 poll 提供 correct options、open_text 提供 options、quiz 提供 selection mode 均為 error。
- 不存在或重複的 option ref、correct option ref 是 error。
- 題型未知、必要欄位缺失、超出長度或選項數量均為 error。

### Warning

- 同一 Course 可以有相同題幹。
- Validation 可用確定性規則提出「可能重複題目」warning，但不得自動合併或阻擋。
- AI Agent 的內容品質、事實正確性或教學建議須另行標示，不得冒充平台 deterministic validation。

### Error／warning 最小語意

所有入口至少回傳：

- 穩定、語言無關的 code。
- 可定位到題目及欄位的 path。
- 繁體中文／英文可翻譯的人類訊息。
- 是否阻擋提交。
- 使用者可採取的下一步。

建議的需求層 error domain：

| Code | 意義 |
|---|---|
| `QUESTION_TYPE_INVALID` | 題型不存在 |
| `FIELD_REQUIRED` | 必要欄位缺失 |
| `FIELD_FORBIDDEN` | 題型不允許該欄位 |
| `TEXT_EMPTY` | trim 後為空 |
| `TEXT_TOO_LONG` | 超過長度上限 |
| `OPTION_COUNT_INVALID` | 選項少於 2 或多於 10 |
| `OPTION_DUPLICATE` | 正規化後選項重複 |
| `OPTION_REF_INVALID` | option ref 缺失、重複或不存在 |
| `CORRECT_OPTION_INVALID` | 正確答案缺失或引用不存在選項 |
| `BATCH_SIZE_INVALID` | 批次少於 1 或多於 50 |
| `COURSE_NOT_EDITABLE` | Course 非 draft 或目前狀態不允許修改 |
| `QUESTION_LOCKED_BY_SESSION` | 操作會改變已建立的 SessionQuestion 快照 |

實際命名若在 M2 調整，必須維持相同穩定語意與 Web／CLI parity。

## Web 與 CLI 操作邊界

### Web 單題 CRUD

- 老師可在自己擁有的 `draft` Course 建立、檢視、修改、刪除及排序 QuestionDefinition。
- 單題操作不受「每批最多 50 題」限制。
- 已存在的 LiveSession 快照不受 QuestionDefinition 修改或刪除影響。
- Course archived 後不得修改題目。

### Web／CLI 批次 command

只有批次建立套用以下規則：

- 每批 1～50 題。
- `client_ref` 在單次 payload 內唯一，只用於 validation 定位與成功結果對照。
- All-or-nothing：任一 error 均不得建立部分題目。
- Validation 一次回報所有可辨識的 error 與 warning。
- Validation 成功後的 preview 必須完整呈現 Course 名稱與 ID、題目順序、內容、正確答案及 warning。
- 正式建立前必須由老師明確確認；payload 改變即重新 validation 與確認。
- 正式建立採相同 validation 結果、授權重查、transaction 與 idempotency 規則。
- 成功題目依預覽順序附加到 Course 當下末端。

### CLI／Agent MVP

2026-09-10 MVP 只要求單一官方驗證 Agent host 的最小端到端流程：

1. 必要 authentication。
2. 查詢有權操作且為 `draft` 的 Course。
3. 產生或接受 1～50 題 payload。
4. 使用本契約共用 validation。
5. 完整 preview。
6. 老師明確確認。
7. 原子建立與安全重試。

完整 key 輪替、跨 OS 發行、進階通知、CSV 與管理功能屬後續範圍，詳見 [[P0 核心需求基線#MVP 範圍]]。

## P0-04 驗收條件

- [x] P0-04-AC-01 Web 與 CLI 的題目輸入均轉成相同 QuestionDefinition 語意並使用同一套 validation 規則。
- [x] P0-04-AC-02 Poll、open text、quiz 的 required／allowed／forbidden 欄位均有明確規則，不依賴範例猜測。
- [x] P0-04-AC-03 相同有效 fixture 經 Web 與 CLI validation 後得到相同 canonical 語意及 warning。
- [x] P0-04-AC-04 相同無效 fixture 經 Web 與 CLI validation 後得到相同 error code 與欄位 path。
- [x] P0-04-AC-05 每批 1～50、`client_ref`、all-or-nothing、validation token 與 idempotency 只套用於批次 command，不限制 Web 單題 CRUD。
- [x] P0-04-AC-06 CLI 建立的題目是一般 QuestionDefinition，`created_via` 只記來源；Web 可依 Course 狀態正常檢視、修改、刪除及排序。
- [x] P0-04-AC-07 LiveSession 啟用時建立 SessionQuestion 不可變快照；後續題目編輯不改變進行中或歷史場次。
- [x] P0-04-AC-08 SessionQuestion closed 後只在該 LiveSession 不可重開，不阻止來源題目跨場重用。
