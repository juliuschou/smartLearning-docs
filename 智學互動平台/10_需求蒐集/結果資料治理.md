# 智學互動平台 - 結果資料治理

> [!important] Phase B privacy override（2026-08-23）
> 本檔早期「學員無帳號」是 MVP scope 前提，已由 Phase B supersede；目前 live session 可有 account-bound Participant，但 archive 治理不因此建立永久學員輪廓。close/archive 前必須解除 account、displayName、participant token 與答案之間的可查關聯；open_text 仍只輸出匿名 plain-text `{ text }`，內容本身可能含個資的 warning 保留。student 不提供歷史結果入口；90-day retention、不可逆刪除、最小 deletion event 與不延長期限規則不變。

> [!important] 單一治理來源
> 本檔是 [[智學互動平台]] P0-06「結果歸檔、查詢、保留與刪除」的現行規範。原始 [[需求蒐集]] 只寫「closed 後結果歸檔可查」且保留期限待確認；自本基線起，以本檔為準。

## 目的與原則

- 歸檔對象是一次 LiveSession，不是整個 Course。
- 結果用於短期教學回顧，不建立永久學員輪廓。
- 學員無帳號，歸檔後不得保存能把答案回連至顯示名或 participant token 的關聯。
- 保存 archive projection 與 governed Submission source data 90 天：poll/quiz archive API 僅提供匿名彙總；open-text archive response 提供匿名 raw `{ text }`；期限後不可逆刪除。
- 查詢、提前刪除與刪除事件須遵守最小權限及資料最小化。

> [!note] 需求與實作邊界
> 本檔定義保存什麼、誰能查看、何時刪除及刪除後留下什麼。資料表、archive storage、aggregation、排程器、partition、backup 與 physical deletion 實作留到 M2。

> [!note] 驗收勾選語意
> 本檔 `[x]` 代表需求內容已確認,不代表功能已實作或測試通過。

## LiveSession 結束與歸檔

LiveSession 進入 `closed` 後：

1. 所有 SessionQuestion 與 Submission 不可再修改。
2. 當時有效 Submission 形成該場權威結果。
3. 即時彙總與歸檔查詢必須對同一權威資料一致。
4. 系統移除顯示名／participant token 與答案之間可被應用程式查詢的關聯。
5. 保存題目快照與統計彙總；poll/quiz raw Submission 僅留在 governed source storage，open-text archive response 僅為匿名 `{ text }`；保留期從 `closed_at` 起算 90 天。
6. LiveSession 因 8 小時 hard limit 自動 closed 時，套用相同歸檔規則。
7. `cancelled` 且從未收集 Submission 的場次不形成 ArchivedResult；只保留必要場次 metadata。

> [!warning] 匿名不等於無敏感內容
> Open text 答案可能由學員自行輸入姓名、聯絡方式或其他個人資料。平台不宣稱能保證內容本身完全匿名；老師與管理員應依最小必要原則查看，發現誤收敏感資料時可啟動提前刪除。

## 歸檔查詢權限

| 角色        | 可查範圍                             | 可見內容                                                               |
| ----------- | ------------------------------------ | ---------------------------------------------------------------------- |
| Course 老師 | 自己擁有 Course 的 LiveSession       | 題目快照、poll/quiz 匿名彙總、open-text 匿名 `{ text }`、場次 metadata |
| 系統管理員  | 全平台 LiveSession，限管理與支援目的 | 與老師相同；不得看已解除的顯示名／token 關聯                           |
| 學員        | 不提供歷史查詢入口                   | 只在場次進行中依 vote-to-reveal／題目 closed 規則看即時結果            |

查詢需求：

- 依 Course、LiveSession、archive 狀態及 `closedAt` 日期範圍篩選；`closedFrom`／`closedTo` 使用帶 UTC/offset 的 ISO date-time，兩端 inclusive，且 filters 必須在 count／pagination 前套用。
- 老師查 foreign-owned LiveSession filter 時回 empty page；foreign detail 以 404 隱藏存在性；student 對 archive list/detail 均拒絕。
- 清單按場次時間倒序顯示，結果量大時使用分頁。
- 顯示資料的 `closed_at` 與預定刪除日期。
- 已刪除或已到期的結果顯示最小狀態，不得重新顯示答案或彙總。
- 老師帳號 disabled 後無法登入查詢；帳號恢復後可再次依 Course 所有權查詢尚未到期結果。
- Course archived 不影響歷史結果查詢與既定刪除期限。

> [!note] Archive immutability boundary
> Active archive payload 在 application/domain boundary 為 create-once：正常 API 沒有 update/rebuild route；只有 BE-5.2/BE-5.3 可執行 governed `active/non-null → deleted/null` tombstone transition。此保證不宣稱能阻止 schema owner／DBA 直接 SQL。

## 保留期限與自動刪除

- 保留期固定為 LiveSession `closed_at` 起 90 天。
- 到期後不可逆刪除：
  - SessionQuestion 快照內容。
  - 匿名原始 Submission。
  - 統計彙總。
  - 顯示名、participant token 與重連資料。
- 不得因 Course archived、老師停用、查詢、備份或匯出而自動延長保留期。
- MVP 不提供 legal hold、老師自行延長或逐場自訂保留期。
- 備份與復原不得使已達刪除期限的資料重新出現在應用程式；具體 backup expiry 與清理機制留待 M2。
- 自動刪除成功後建立不含內容的最小刪除事件，記錄場次 ID、刪除時間、觸發類型 `retention_expired`、資料類別與筆數。

## 提前刪除

### 權限與流程

- Course 老師可以提出提前刪除申請，但不能直接刪除資料；申請必須選擇固定原因類別 `privacy|support`。
- 系統管理員經有效登入與 step-up、明確確認後執行提前刪除；確認 reason 必須與該 Teacher request reason 完全一致，不提供管理員另行改判類別。
- Reason 不一致（含已完成 request 的 conflicting replay）必須在任何 destructive write 前回穩定 HTTP 409；同 request/session/reason 的重試回 canonical result。request/session identity 不匹配仍以 404 隱藏存在性。
- 刪除範圍是指定 LiveSession 的全部 ArchivedResult，不支援只刪某位 participant 或單一答案，避免重建身分關聯及不完整彙總。
- 管理員不得預覽或下載將刪除資料作為刪除前備份。
- 刪除不可復原，不得以還原、重新彙總或舊備份重新顯示。

### 刪除事件

提前刪除後只保留：

- LiveSession ID 與 Course ID。
- 申請者 actor 類型與執行者管理員不可變 ID。
- 申請／執行時間。
- 固定原因類別及不含答案內容的簡短說明。
- 已刪除的資料類別與筆數。
- 結果 `success`／`failure` 及穩定錯誤碼。

刪除事件不得包含：

- 題幹、選項、正確答案。
- Open text 或其他原始答案。
- 統計彙總。
- 顯示名、participant token 或可識別資料。

## MVP 不提供

- 學員歷史結果入口。
- 老師直接永久刪除。
- 結果刪除後復原。
- 老師或管理員匯出互動結果。
- 每個 Course／LiveSession 自訂保留期限。
- 永久保存彙總或匿名原始答案。
- 由顯示名或 participant token 查詢個別學員歷史。

## P0-06 驗收條件

- [x] P0-06-AC-01 LiveSession closed 後，SessionQuestion、Submission 與結果不可再修改，新答案全部被拒絕。
- [x] P0-06-AC-02 歸檔以 LiveSession 為單位，能區分同一 Course 不同場次的題目快照、答案與彙總。
- [x] P0-06-AC-03 歸檔前解除顯示名／participant token 與答案的可查關聯；archive API 對 persisted/legacy payload 採 nested strict allowlist：poll/quiz 僅輸出 aggregate，open-text 僅輸出匿名 `{ text }`。Poll/quiz raw Submission 只留在 governed source storage；Submission 在 governed purge 前可仍指向已匿名化 Participant，但不得透過正常 API 重建 answer-to-person linkage。
- [x] P0-06-AC-04 老師只能查自己 Course 的結果；管理員可依管理職責查全平台；學員沒有歷史查詢入口。
- [x] P0-06-AC-05 結果從 `closed_at` 起保存 90 天，並顯示預定刪除日期。
- [x] P0-06-AC-06 90 天到期後不可逆刪除題目快照內容、匿名原始答案、彙總與 participant 資料，不保留永久影子彙總。
- [x] P0-06-AC-07 老師可提出提前刪除申請，但只有管理員可用相同 reason 確認執行；reason conflict 必須無副作用地回 409，matching replay 必須 canonical/idempotent；刪除以整個 LiveSession 為範圍且不可復原。
- [x] P0-06-AC-08 刪除後只保留不含題目及答案內容的最小事件；舊備份不得讓已刪資料重新出現在應用程式。
- [x] P0-06-AC-09 Course archived、老師 disabled 或資料被查詢均不改變既定 90 天期限。
- [x] P0-06-AC-10 MVP 不提供結果匯出、自訂保留期、legal hold、學員歷史查詢或刪除後復原。

## M2 設計輸入

- ArchivedResult 與 LiveSession metadata 的資料模型及權限查詢。
- 顯示名／participant token 去關聯與清理時機。
- 即時彙總與歸檔一致性。
- 90 天 retention job、重試、失敗告警與 idempotency。
- 提前刪除 preview、確認、transaction 與稽核事件。
- Backup retention、restore filter 與已刪資料防復活。
- Open text 安全顯示、輸入編碼與管理支援流程。
- 分頁、索引、查詢效能與刪除後 tombstone 呈現。
