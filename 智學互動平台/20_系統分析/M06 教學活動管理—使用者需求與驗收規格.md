# M06 教學活動管理—使用者需求與驗收規格

> **來源：**《即時互動教學系統 — 系統功能規劃書 V1.2》M06（教學活動管理）、M11 活動模式與競賽規則，以及相關角色權限矩陣、資料模型與業務規則  
> **模組優先級：** P0  
> **規格狀態：** 依 V1.2 整理；未由來源明確定義的政策集中列於待確認事項，不得由實作逕自假設。

## 1. 需求概覽與假設

- **功能目標：** 讓老師建立及維護自己的教學活動、選用題庫、提供學員加入資訊、設定互動與參與模式、追蹤活動狀態並結束活動，同時保留活動當時的題目內容與結果。
- **範圍：** 涵蓋 M06-01～M06-10：建立活動、選擇題庫、產生 Game PIN／QR Code／活動連結、活動設定、活動清單、結束活動、選擇分組模式、設定排名與計分選項、條件式分組參數，以及首次計分前的模式異動檢查。
- **操作者與權限：** 由已登入且啟用、具備 M04 所定 M06 權限的老師操作。老師僅能查詢及維護自己主持的活動；`SYSTEM_ADMIN` 不因管理者角色自動取得老師功能。後端每次請求均須驗證權限、活動主持者及活動狀態。
- **學員身分：** 學員為單場活動的臨時參與者，不需正式帳號；活動加入與後續互動依活動憑證及 Session 狀態控制。匿名顯示不得取消系統區分同場參與者所需的識別能力。
- **模式預設：** 新活動預設 `grouping_mode=INDIVIDUAL`、`leaderboard_mode=NONE`。不分組可選無排名或個人排名；分組可選無排名或團隊排名。V1 不提供分組模式下的個人排名，也不允許不分組時使用團隊排名。
- **模式異動界線：** 第一題計分題開放前可變更分組／不分組及相容的排行榜模式；第一道計分題開放後鎖定至活動結束。活動「開始」與「第一道計分題開放」為不同事件，不得混為一談。
- **題庫與歷史資料：** 活動須保存當時使用的題目快照（`SESSION_QUESTION`）。來源題庫後續修改或刪除，不得改變既有活動的題目、作答解讀或歷史結果。
- **範圍界線：** M06 管理活動層級資料與設定；題目開放／關閉及結果公布由 M07 控制，學員加入與作答由 M08 管理，統計及計分由 M09／M11 契約定義。組織間競賽為 P1，不納入本模組 V1 可執行範圍。

## 2. 功能範圍

| 功能 ID | 功能名稱 | 功能說明 | 範圍界線 |
|---|---|---|---|
| M06-01 | 建立教學活動 | 設定活動名稱、日期、主辦單位並建立活動。 | 老師建立的活動歸屬該老師；其他欄位必填性與格式依欄位契約及待確認事項。 |
| M06-02 | 選擇題庫 | 指定活動要使用的題庫／題目。 | 只可選用老師有權使用的題庫；活動需保存不可變題目快照。 |
| M06-03 | 產生加入資訊 | 提供 Game PIN、QR Code 及活動連結。 | 三者均導向同一活動加入流程；有效期限、輪替與撤銷政策待確認。 |
| M06-04 | 活動設定 | 設定暱稱、匿名、計分及排行榜選項。 | 排行榜相容性及公布時機須遵循本文件與 M07／M09 契約；未核定的預設值不得自行推定。 |
| M06-05 | 活動清單 | 查詢尚未開始、進行中及歷史活動。 | 僅回傳操作者有權查看的活動；狀態定義及排序／分頁依平台契約或待確認事項。 |
| M06-06 | 結束活動 | 結束 Session 並保留活動結果。 | 結束不等同刪除；結束後加入及互動行為依 M07／M08 契約拒絕或限制。 |
| M06-07 | 活動參與模式 | 選擇 `INDIVIDUAL`（不分組）或 `TEAM`（分組）。 | 新活動預設 `INDIVIDUAL`；只有 `TEAM` 才存在隊伍及組員關聯。 |
| M06-08 | 排名與計分設定 | 不分組選 `NONE`／`INDIVIDUAL`；分組選 `NONE`／`TEAM`。 | 預設 `NONE`；計分定義由 M09／M11 負責。 |
| M06-09 | 分組參數（條件顯示） | 分組時設定隊伍數、自訂隊名及分組方式等參數。 | 僅 `TEAM` 模式適用；隊伍建立、分派與調整規則依 M11。 |
| M06-10 | 模式異動檢查 | 在首道計分題開放前允許調整模式；開始計分後鎖定。 | 觸發點為第一道計分題開放；不得回溯改變已產生分數或歷史快照。 |

## 3. 使用者故事

> **身為**具備 M06 權限且主持該活動的老師，  
> **我希望**建立教學活動、選用題庫、設定參與及排名模式、提供加入資訊，並檢視或結束自己的活動，  
> **以便於**依授課情境安全地組織現場互動，並保留可追溯且一致的活動結果。

## 4. 活動生命週期與模式規則

### 4.1 活動狀態概念

規劃書列出「尚未開始、進行中、歷史活動」三類清單。此為清單分類，不足以完整決定所有狀態轉換；狀態名稱、起訖條件、是否允許恢復及重複結束語意須依平台／M07 契約確認。至少應能識別活動尚未啟動、進行中及已結束，且不得將已結束活動重新當作可加入或可作答的活動。

### 4.2 分組與排行榜相容性

| `grouping_mode` | `leaderboard_mode` | V1 規則 |
|---|---|---|
| `INDIVIDUAL` | `NONE` | 允許，預設；個人問答、投票及文字回饋，不建立隊伍。 |
| `INDIVIDUAL` | `INDIVIDUAL` | 允許；個人排名僅於老師公布後顯示。 |
| `TEAM` | `NONE` | 允許；可建立隊伍及合作互動，不顯示排行榜。 |
| `TEAM` | `TEAM` | 允許；團隊計分及排行榜依 M11，且僅於老師公布後顯示。 |
| `INDIVIDUAL` | `TEAM` | 不允許；沒有隊伍不得產生團隊排名。 |
| `TEAM` | `INDIVIDUAL` | V1 不提供；避免個人與團隊競賽概念混淆。 |

模式相容性必須由後端驗證。若模式尚可變更，改為 `INDIVIDUAL` 時不得建立隊伍、隊員關聯或團隊結算資料；既有活動含分組資料時的清理／保留規則須與 M11 資料契約一致並列為待確認，不得使歷史結果遭到無聲改寫。

## 5. 驗收條件

```gherkin
Feature: M06 教學活動管理

  Background:
    Given 操作者已登入且帳號為啟用狀態
    And 操作者具備 M04 授權矩陣所定的 M06 對應功能權限
    And 所有活動讀寫均由後端驗證活動主持者及允許的活動狀態

  Scenario: 建立活動並套用預設模式
    Given 老師提供符合欄位契約的活動資料
    When 老師建立活動且未指定分組或排行榜模式
    Then 系統建立歸屬該老師的活動
    And 活動的 grouping_mode 為 INDIVIDUAL
    And 活動的 leaderboard_mode 為 NONE
    And 系統不建立 SESSION_TEAM、TEAM_MEMBERSHIP 或 TEAM_SCORE_LEDGER

  Scenario: 必填資料或欄位格式驗證失敗
    Given 老師提交缺少核定必填欄位或格式不符的活動資料
    When 老師建立或更新活動
    Then 系統拒絕該次異動並指出可修正欄位
    And 不留下部分活動或不一致的關聯資料
    And 原有活動資料維持不變

  Scenario: 活動選用本人可存取的題庫並建立快照
    Given 老師具備 M05 讀取權限且指定題庫屬於其可存取範圍
    When 老師將題庫加入活動並完成活動建立或核定的快照時點
    Then 系統保存該活動使用的題目快照及其必要題型、選項與答案內容
    And 快照與來源題庫及題目具有可追溯關聯
    And 活動不得只依賴會隨來源題庫修改而變動的即時內容

  Scenario: 不得選用未授權的題庫
    Given 指定題庫不存在、已刪除或不屬於老師可存取範圍
    When 老師嘗試將該題庫加入活動
    Then 系統拒絕該要求
    And 不回傳題庫內容或建立部分活動題目快照

  Scenario: 來源題庫異動不影響已建立活動
    Given 活動已建立題目快照
    When 老師修改或刪除來源題庫中的題目、選項或答案
    Then 活動快照、既有作答解讀及活動結果保持不變
    And 來源題庫的新內容僅供後續活動選用

  Scenario: 產生活動加入資訊
    Given 活動處於允許學員加入的狀態
    When 老師要求產生加入資訊
    Then 系統提供該活動的 Game PIN、QR Code 及活動連結
    And 三種資訊均指向同一活動的加入流程
    And 加入資訊不得包含密碼、Session Token 或不必要的個人資料

  Scenario: 已結束活動不得接受新的加入資訊或加入要求
    Given 活動已結束
    When 老師要求產生可用加入資訊或學員使用既有資訊加入
    Then 系統依活動狀態拒絕新的加入
    And 不建立新的參與者或作答資料
    And 活動既有結果及快照保持可供授權者查詢

  Scenario: 設定允許的分組與排行榜組合
    Given 活動尚未開放第一道計分題
    When 老師設定 INDIVIDUAL 與 NONE／INDIVIDUAL，或 TEAM 與 NONE／TEAM 的組合
    Then 系統驗證組合有效並保存設定
    And 個人或團隊排行榜僅在老師依 M07 規則公布後對學員顯示

  Scenario: 拒絕不相容或 V1 不支援的模式組合
    Given 老師提交 INDIVIDUAL 與 TEAM，或 TEAM 與 INDIVIDUAL 的組合
    When 系統驗證活動設定
    Then 系統拒絕該異動並指出模式組合不支援
    And 活動原有設定、隊伍資料及分數保持不變

  Scenario: 僅分組模式接受分組參數
    Given 活動的 grouping_mode 為 INDIVIDUAL
    When 老師提交隊伍數、自訂隊名或分組方式等分組參數
    Then 系統拒絕或忽略該等不適用參數，依核定 API 契約回覆
    And 不建立任何隊伍或隊員關聯
    When 老師將活動設定為 TEAM 且仍未開放第一道計分題
    Then 系統允許依 M11 規則設定分組參數

  Scenario: 首道計分題開放前可變更參與模式
    Given 活動尚未開放任何計分題
    And 活動已加入學員或已設定分組資料
    When 主持老師變更 grouping_mode 及相容的 leaderboard_mode
    Then 系統依新模式保存設定
    And 不得改寫任何已結算分數或歷史題目快照
    And 資料變更須符合 M11 的隊伍資料一致性契約

  Scenario: 第一題計分開放後鎖定模式
    Given 活動已開放第一道計分題
    When 老師嘗試切換 grouping_mode 或 leaderboard_mode
    Then 系統拒絕模式異動
    And 已產生的隊伍、題目資格快照、作答與分數保持不變
    And 活動模式維持已鎖定狀態直到活動結束

  Scenario: 查詢自己的活動清單
    Given 老師擁有尚未開始、進行中或已結束的活動
    When 老師查詢活動清單
    Then 系統只回傳該老師有權查看的活動
    And 每筆活動呈現可辨識的狀態分類
    And 查詢不改變活動狀態或設定

  Scenario: 老師不得查詢或維護他人活動
    Given 指定活動不屬於目前老師或老師不是該活動主持者
    When 老師查詢、更新設定、產生加入資訊或結束該活動
    Then 後端拒絕該操作
    And 不回傳非授權活動內容或執行任何異動

  Scenario: 結束活動並保留結果
    Given 活動由目前老師主持且處於可結束狀態
    And 活動已有題目快照、參與者、作答或統計資料
    When 老師結束活動
    Then 系統將活動標記為已結束
    And 保留題目快照、作答、統計、分數及稽核所需資料
    And 活動不得再接受新的互動或分數異動，除非 M07／M08 明確允許的唯讀操作

  Scenario: 未登入、帳號停用或欠缺功能權限
    Given 操作者未登入、帳號已停用或不具備所需 M06 權限
    When 操作者查詢或異動活動
    Then 後端拒絕該要求
    And 不回傳受限活動資料或執行異動
    And 前端隱藏控制項不得取代後端授權檢查

  Scenario: 並行開題與模式變更
    Given 主持老師同時提出開放第一道計分題及變更分組／排行榜模式的要求
    When 兩項要求並行抵達系統
    Then 系統以原子化狀態轉換決定唯一有效順序
    And 一旦第一道計分題成功開放，後續模式變更均遭拒絕
    And 不得產生模式與題目資格／分數彼此不一致的活動資料

  Scenario: 必要依賴無法驗證或儲存
    Given 權限、題庫、活動儲存或加入資訊服務無法完成必要操作
    When 老師建立、查詢、更新或結束活動
    Then 系統不得將未完成操作視為成功
    And 寫入不得留下部分活動、快照或加入資訊資料
    And 系統依平台錯誤契約回覆可重試的服務錯誤且不洩露內部資訊
```

## 6. 資料、欄位與邊界規則

- **活動基本資料：** 至少涵蓋活動名稱、日期、主辦單位及活動擁有者／主持者。名稱、日期、主辦單位的必填性、字串長度、日期範圍與時區尚未由 V1.2 明確規定，應依核准欄位契約驗證；不得自行新增未核定的限制值。
- **活動模式欄位：** `grouping_mode` 僅接受 `INDIVIDUAL`、`TEAM`，預設 `INDIVIDUAL`；`leaderboard_mode` 僅接受 `NONE`、`INDIVIDUAL`、`TEAM`，預設 `NONE`。只允許 `INDIVIDUAL + NONE/INDIVIDUAL` 與 `TEAM + NONE/TEAM`。前端條件顯示之外，後端與資料層亦須驗證相容性。
- **分組資料：** `SESSION_TEAM`、`TEAM_MEMBERSHIP` 僅在 `TEAM` 模式使用；隊伍數、名稱、分派方式及成員調整依 M11 契約。`INDIVIDUAL` 模式不可產生隊伍、隊員關聯或團隊結算資料。首道計分題開放後隊伍及模式凍結規則依 M11。
- **計分與排名：** M06 僅保存活動選項，不自行決定每題配分、有效人數快照、平均方式或並列名次；這些規則依 M09／M11。排行榜預設不啟用；啟用後仍須由老師明確公布，不能因設定而自動對學員公開。
- **題庫及題目快照：** 活動須以 `SESSION_QUESTION` 或等效不可變資料保存活動使用的題目內容及歷史解讀所需資料。快照建立的精確時點（選題時、建立活動時或啟動時）須由 M05／M06 工程契約核定；不論時點，題庫後續編輯不得回溯修改已生效的活動快照。
- **加入資訊：** Game PIN、QR Code 及活動連結是活動加入途徑，不應視為正式帳號憑證。PIN 格式／唯一性範圍、有效期限、輪替、撤銷及防濫用限制待確認。活動結束或加入憑證失效時，不得建立新參與者。
- **暱稱與匿名：** 暱稱唯一性、系統分配規則、匿名對老師／學員／報表的可見範圍及個資保留期限待確認。無論顯示匿名或暱稱，系統仍須在單場活動內唯一區分參與者，並避免重連建立重複參與者身分（BR-009、BR-020）。
- **活動清單：** 至少支援尚未開始、進行中及歷史活動分類；各狀態的判定條件、排序、分頁、篩選及歷史活動是否等同已結束，依平台清單契約或需求確認，不得以日期推測取代明確狀態。
- **結束及保留：** 結束活動須保留題目快照、作答、統計、分數及稽核必要資料。是否允許恢復、封存／刪除政策、結果可見期限及個資匿名化依平台與 M10 政策，不由 M06 擅自規定。
- **稽核：** 活動建立、設定異動、模式切換、加入資訊管理及結束活動依 M10 全域稽核契約記錄；事件欄位、成功／失敗範圍及保存期限沿用 M10，不記錄秘密或不必要的個資。

## 7. 非功能性需求

- **後端授權：** 所有 M06 API／Action 均須驗證登入狀態、帳號有效狀態、M04 對應功能權限及活動主持者範圍。建議讀取使用 `M06_READ`、建立／修改／結束使用 `M06_WRITE`；實際 API 映射由平台團隊依 M04 權限目錄核定。無法完成授權驗證時採拒絕，不得 fail-open。
- **資料完整性與原子性：** 建立活動、選用題庫、建立快照及產生加入資訊的多步驟寫入須避免部分成功；失敗時回復到一致狀態。模式相容性、活動狀態及主持者檢查須在後端執行。
- **併發一致性：** 開放首道計分題與模式異動須採原子化檢查／更新，避免併發請求造成一邊已計分、一邊仍允許切換。結束活動亦須阻止與其競爭的加入／作答操作違反已結束狀態。
- **歷史一致性：** 已建立的 `SESSION_QUESTION` 快照及已產生結果不可因來源題庫更新、活動設定變更或活動結束而被無聲改寫；活動後續結果依 M09／M11 規則解讀。
- **隱私與加入安全：** 加入資訊應只包含加入活動所需資料；不得暴露管理端憑證、其他學員個資或跨組織原始作答。匿名設定只影響核准的顯示／報表範圍，不得使活動參與者無法去重及防止重複計分。
- **可稽核性：** 活動重要異動依 M10 可追查操作者、時間、目標及結果；稽核不可包含密碼、Token 或完整不必要的參與者敏感資料。
- **可用性與效能：** 活動清單、活動讀寫、加入資訊及狀態轉換效能門檻沿用平台整體 NFR，不設定未核准數值。依賴服務不可用時須回覆可重試錯誤且保持資料一致。

## 9. 待確認事項

下列政策在 V1.2 未完整定義，需求／平台負責人須確認後才能形成更細的工程契約；在確認前不得由實作自行選定具體值：

1. 活動名稱、日期、主辦單位的必填性、格式／長度、日期時區及是否允許過去日期。
2. 活動建立、題庫選取、活動啟動等時點中，何者為題目快照的正式建立點；活動建立後是否允許明確重新同步題庫（建議預設不重新同步，除非另有新快照版本）。
3. Game PIN 格式、長度、唯一性範圍、有效期間、重複產生／輪替與撤銷行為；活動連結及 QR Code 是否可獨立撤銷。
4. 活動建立、啟動及結束的完整狀態機；結束是否可恢復、重複結束的冪等結果，以及結束後學員可檢視哪些已公布結果。
5. 暱稱是否必填、重複暱稱處理、系統分配格式；匿名對主持老師、投影畫面及報表各自隱藏哪些資料。
6. 活動計分預設值、允許計分的題型及選項；具體配分、有效人數和累計規則由 M09／M11 確認。
7. 首道計分題開放前已建立的隊伍／組員資料，在切回 `INDIVIDUAL` 時應刪除、保留為無效紀錄或封存；須確保不可回溯變更既有結果。
8. 活動清單的排序、篩選與分頁，以及「歷史活動」和「已結束」的精確對應關係。
9. M04 權限目錄中 `M06_READ`／`M06_WRITE` 的核定與各 API／Action 對應；哪些操作需要額外 `M07_WRITE` 或 M11 權限。
10. 活動資料、參與者資料、作答及結果保存期限、匿名化政策及各類稽核事件保存期限；依 M10／平台資料治理政策核定。

## 10. 跨模組契約

- **M01 帳號與登入：** 提供已登入使用者及帳號有效狀態；停用帳號或無效 Session 不得存取 M06 受保護功能。
- **M02 角色管理／M03 老師維護：** 提供有效角色及老師帳號狀態；老師停用不刪除其歷史活動、題目快照或結果。`SYSTEM_ADMIN` 不自動取得授課權限。
- **M04 角色與功能對應：** 權限目錄登錄並映射 M06 讀取／寫入 API；每次後端呼叫另檢查活動主持者與活動狀態。建議 `M06_READ` 控制清單／檢視，`M06_WRITE` 控制建立／修改／加入資訊管理／結束，最終映射須由平台團隊核定。
- **M05 題庫管理：** 提供老師可選用題庫的授權範圍及題目內容；M06 建立活動題目快照，M05 後續修改不得改寫快照。題庫刪除與活動歷史保留須相容。
- **M07 老師即時控制台：** 區分啟動活動、選題、開放／停止作答、公布結果及結束活動。M06 模式鎖定觸發訊號為「第一道計分題開放」，M07 須提供可靠且可原子化檢查的狀態轉換。
- **M08 學員互動管理：** 以 PIN、QR Code 或連結加入同一場活動；依活動狀態及憑證效期控制加入。匿名／暱稱展示不得破壞參與者唯一識別、斷線重連及防止重複作答的規則。
- **M09 即時統計與結果分析：** 提供活動摘要及正確率等結果；計分題型、個人得分及個人排行榜依 M09 契約，排行榜需遵循老師公布狀態。
- **M10 系統設定與稽核：** 定義活動建立、異動、結束及必要失敗事件的稽核欄位、遮罩與保存期限；M06 不另訂全域稽核政策。
- **M11 可選分組與團隊競賽：** 提供隊伍、成員、隨機分組、鎖定、遲到者、團隊計分與排行榜規則；M06 僅管理是否啟用分組及活動層級模式設定。組織間競賽屬 P1。
- **平台共通契約：** 錯誤回應、分頁、併發控制、交易原子性、狀態轉換、效能門檻及依賴不可用處理沿用平台政策；無法完成權限或資源驗證時不得 fail-open。
