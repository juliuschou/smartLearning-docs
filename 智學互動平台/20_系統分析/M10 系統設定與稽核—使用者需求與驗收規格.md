# M10 系統設定與稽核—使用者需求與驗收規格

> **來源：**《即時互動教學系統 — 系統功能規劃書 V1.2》M10（系統設定）、M01 登入安全與 Session、M03 老師帳號生命週期、M04 權限管理、M06 活動管理及 BR-001、BR-004～BR-006。
> **模組優先級：** P1。
> **規格狀態：** 草案；V1.2 僅列出功能項目，未定義具體參數、稽核欄位與保留期限。本文不臆定政策數值；須依跨模組契約核定後實作。

## 1. 需求概覽與假設

- **功能目標：** 提供系統管理者維護核准的全域系統參數、查詢必要的登入及管理稽核事件，並掌握進行中活動及其連線狀態，以支援平台營運與問題追查。
- **範圍：** 涵蓋 M10-01～M10-05：基本參數設定、系統使用紀錄、權限異動紀錄、老師帳號異動紀錄、活動監控。M10 為 P1，不作為 P0 MVP 上線門檻。
- **主要使用者：** 系統管理者依規劃書權限矩陣管理系統設定與稽核紀錄。活動監控的可見角色與資料範圍尚未由 M10 明確指定，須經權限政策確認；未確認前不視為老師的既定功能。
- **設定範圍假設：** 參數目錄、可修改範圍與執行期生效方式均未由來源完整定義；本文以「核准的活動預設值、Session 逾時等參數」作規格整理假設。是否允許修改其他設定、秘密或部署層參數，須由產品／平台政策確認。
- **稽核資料來源：** 登入／登出事件由 M01 提供；角色功能授權變更由 M04 提供；老師建立、修改、停用事件由 M03 提供。M10 負責查詢及適用的保存政策，不取代來源模組的事件產生責任。
- **活動監控範圍：** 來源明定可查看進行中活動及連線狀態；監控欄位、可見角色及是否提供更細資料均待確認。監控與 M07 活動控制的界線依主持老師控制活動原則整理，屬跨模組假設，仍須核定。
- **權限原則：** 所有查詢與設定變更均由後端驗證角色功能權限及資料範圍。前端隱藏功能不得取代後端授權。
- **資料保存假設：** 保存、刪除／匿名化及查詢期間尚無核定數值，列為平台資料治理待決策事項；本文不定義期限。

## 3. 使用者故事

> **身為**具備 M10 權限的系統管理者，
> **我希望**維護核准的系統參數、追查帳號與權限異動，並查看進行中活動的營運狀態，
> **以便於**維持平台設定一致、支援安全稽核並及早發現服務或連線問題。


## 4. 權責與資料規則

### 4.1 系統參數變更

1. 來源僅舉活動預設值、Session 逾時為例，未提供完整參數目錄。參數代碼、型別、允許範圍、預設值、敏感等級、生效方式及影響範圍列為設定規格待核定項目。
2. 系統參數變更須受 M04 權限檢查；哪些角色可修改哪些參數及後端驗證規則，依核准的權限矩陣與參數契約落實。
3. 參數批次更新的原子性、參數相依驗證及併發衝突處理未由來源指定，需由平台 API／資料一致性契約核定，不視為來源已確認需求。
4. 變更的生效時點及對既有活動／Session 的影響須逐項定義；不得在未經核准下推定即時生效或回溯改寫活動設定。
5. Session 逾時由 M01 定義其安全政策及執行語意；M10 可調整範圍、最低／最高值及既有 Session 的套用方式待 M01／平台契約確認。

### 4.2 稽核事件

1. 來源要求記錄使用者登入／登出、角色功能授權異動及老師帳號建立／修改／停用等事件。事件產生者、操作與事件一致性、查詢欄位及跨模組傳遞方式須由 M01／M03／M04 契約確認。
2. 查詢條件、排序、分頁、查詢上限及時間時區尚未定義，列為待確認的查詢契約；不得當作已核定的介面需求。
3. 成功／失敗事件記錄範圍及事件內容須依安全稽核政策確認。認證秘密不得寫入稽核紀錄，依 M01 不得以登入回應洩露帳號狀態。
4. 權限異動是否須包含完整前後授權值、老師帳號事件的詳細欄位及個資遮罩策略待核定；來源僅確定應記錄相應異動事件。
5. 稽核紀錄的修改／刪除限制、唯增完整性控制及更正方式未由來源說明，應由安全與資料治理政策決定，不列為已確認驗收條件。
6. 保存期限、到期清除／匿名化方式及清除稽核要求尚待資料治理政策核定。

### 4.3 活動監控

1. 來源要求查看進行中的活動及連線狀態；活動識別欄位、連線狀態指標粒度、是否顯示參與者層級資料及更新時間均待需求／平台契約核定。
2. 連線狀態定義、更新週期及資料過期或依賴服務不可用時的呈現方式尚未定義，需與 M08／平台共通 NFR 確認。
3. 系統設定與稽核屬系統管理者管理範圍；M10-05 活動監控是否限系統管理者、是否授予老師活動範圍查詢權，須由 M04 權限政策明訂。
4. 活動控制由 M07 主持老師負責；M10 監控是否完全唯讀及是否提供操作入口，應於功能邊界確認。未確認前不應將監控操作視為可改變活動狀態。
5. 監控可見的學員識別、答案、文字回饋及未公布結果等資料欄位尚待資料最小化與產品政策確認；不得把本文假設當成來源已確認的欄位限制。

## 6. 資料、欄位與邊界規則

- **系統參數：** 規劃書舉例活動預設值及 Session 逾時；參數代碼、型別、目前／預設值、允許範圍、生效方式及適用範圍待核定。認證秘密保護依 M01／平台安全政策處理。
- **活動預設值：** 預設值作用於哪些活動、是否影響既有活動及變更生效時點尚待確認；與 M06 鎖定模式或歷史快照的交互規則需由 M06／M10 契約界定。
- **Session 逾時：** M01 定義登入 Session 逾時語意；閒置／絕對逾時、是否可由 M10 調整、角色差異及既有 Session 生效策略待確認。
- **稽核事件欄位：** 來源尚未定義完整欄位。事件 ID、類別、時間、操作者、目標及結果等為建議候選欄位，須依稽核目的與資料最小化政策核定。
- **時間與查詢：** 時區、時間精度、預設查詢期間、最大區間、排序、分頁、保留期限與匯出能力待平台契約核定。
- **活動監控欄位：** 來源要求進行中活動及連線狀態；活動識別欄位、在線定義、參與者資料粒度、資料更新時間及新鮮度門檻均待 M08／平台契約核定。
- **敏感資料：** 密碼、Token、Session 識別秘密及重設憑證的處理遵循 M01／平台安全政策；活動監控是否顯示原始作答、文字回饋或學員識別資料須經資料最小化及產品政策確認。
- **資料範圍：** 規劃書將系統設定與稽核紀錄列於系統管理者權限；活動監控的可見角色與活動範圍另待 M04 權限政策明訂。
- **待確認事項：** (1) M10-01 可修改參數完整清單、預設值、上下限及生效範圍為何？(2) Session 逾時是否允許於執行期設定，既有 Session 如何套用新值？(3) 稽核事件最低欄位、失敗事件記錄範圍、查詢條件及保存／匿名化期限為何？(4) 稽核紀錄是否需要唯增／防竄改、匯出或法律保全控制？(5) 活動監控的連線狀態定義、更新週期／新鮮度門檻、欄位粒度及可見角色為何？(6) M10 監控是否需要告警或僅提供查詢？(7) M10 上線前哪些安全事件需由 M01／M03／M04 保證記錄？

## 7. 非功能性需求

- **安全授權：** 每個 M10 查詢與寫入請求均須由後端驗證帳號狀態、功能權限及資料範圍；驗證依賴不可用時採拒絕存取，不得 fail-open。
- **安全授權：** M10 查詢與變更須遵循已核定的角色及資源權限；精確角色、活動範圍與拒絕行為由 M04／各功能契約明訂。
- **設定完整性：** 參數型別／範圍驗證、批次更新原子性及併發衝突策略尚非來源已確認要求，依平台參數 API 契約核定後納入驗收。
- **稽核完整性：** 記錄事件為來源明定功能；事件與狀態變更一致性、不可變性、稽核儲存故障時是否 fail-closed，須由安全政策與來源模組契約決定。
- **隱私與資料最小化：** 稽核與監控的實際資料欄位遵循核准的安全／隱私政策；不得將未核定欄位限制誤認為 M10 來源規格。
- **服務狀態可信度：** 活動連線狀態的新鮮度標示、過期／故障降級方式及延遲門檻由 M08／平台共通 NFR 核定。
- **效能與可用性：** 稽核查詢範圍、分頁、監控刷新頻率及服務目標依平台共通 NFR 確認。
- **保存與清除：** 稽核／監控資料的保留期限、刪除或匿名化方式依核准資料治理政策決定。

## 9. 跨模組契約事項

- **M01 帳號與登入管理：** 提供登入、登出及安全事件；Session 逾時由 M01 執行，M10 不得取代認證判斷。須定義事件欄位、操作者識別與安全秘密遮罩。
- **M03 老師維護與管理：** M10-04 來源列明記錄老師建立、修改、停用操作；是否記錄啟用事件及目標識別欄位，依 M03 生命週期與事件契約確認。停用老師使憑證失效依 M03／M01 規則處理。
- **M04 角色與功能對應管理：** 提供權限授權異動事件及目前 M10 功能權限；M10 查詢自身稽核資料亦須經 M04 授權。事件須能與授權批次變更結果對應。
- **M06 教學活動管理：** 提供活動識別、活動狀態及活動設定；M10 不修改活動設定或歷史快照。
- **M07 老師即時控制台：** 活動控制由主持老師負責；M10 監控是否唯讀及是否需要操作入口，需於 M10／M07 功能邊界核定。
- **M08 學員互動管理／平台連線服務：** 提供連線狀態的權威定義、更新時間及故障語意；在線狀態不得與已加入人數、作答資格或已作答人數混用。
- **平台資料治理／NFR：** 定義事件保存、刪除／匿名化、查詢效能、時間時區、事件一致性、稽核儲存故障處置及監控資料刷新門檻。
