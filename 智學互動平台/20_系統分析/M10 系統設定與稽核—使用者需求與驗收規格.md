# M10 系統設定與稽核—使用者需求與驗收規格

> **來源：**《即時互動教學系統 — 系統功能規劃書 V1.2》M10（系統設定）、M01 登入安全與 Session、M03 老師帳號生命週期、M04 權限管理、M06 活動管理及 BR-001、BR-004～BR-006。
> **模組優先級：** P1。
> **規格狀態：** 草案；已納入需求決策 D02–D09。尚未核定的參數上下限、查詢／保存政策及監控刷新門檻依平台政策補充；防竄改、匯出及法律保全另行審查。

## 1. 需求概覽與假設

- **功能目標：** 提供系統管理者維護核准的全域系統參數、查詢必要的登入及管理稽核事件，並掌握進行中活動及其連線狀態，以支援平台營運與問題追查。
- **範圍：** 涵蓋 M10-01～M10-05：基本參數設定、系統使用紀錄、權限異動紀錄、老師帳號異動紀錄、活動監控。M10 為 P1，不作為 P0 MVP 上線門檻。
- **主要使用者：** 系統管理者管理系統設定、稽核紀錄及活動監控；活動監控限管理者，呈現活動與彙總連線摘要。
- **設定範圍：** M10-01 先涵蓋活動預設值及 Session 逾時。設定值及允許範圍依平台政策核定；變更只套用於新建立的活動或 Session，不回溯修改既有項目。
- **稽核資料來源：** M01 提供成功登入／登出事件；M04 提供角色功能授權異動；M03 提供老師帳號建立、修改、停用等事件。核心安全敏感異動須在 M10 查詢 UI 上線前即可追溯。
- **活動監控範圍：** 系統管理者查詢進行中活動及彙總連線狀態；監控以查詢為主，不含告警。狀態過期或不可得時標示「未知」，可得時顯示最後更新時間；刷新門檻由平台契約核定。
- **權限原則：** 所有查詢與設定變更均由後端驗證角色功能權限及資料範圍。前端隱藏功能不得取代後端授權。
- **資料保存假設：** 查詢條件、保存與匿名化期限由平台資料治理政策核定；防竄改、匯出及法律保全另由安全／法務審查，不作本版驗收門檻。

## 3. 使用者故事

> **身為**具備 M10 權限的系統管理者，
> **我希望**維護核准的系統參數、追查帳號與權限異動，並查看進行中活動的營運狀態，
> **以便於**維持平台設定一致、支援安全稽核並及早發現服務或連線問題。

## 4. 權責與資料規則

### 4.1 系統參數變更

1. M10-01 僅納入活動預設值及 Session 逾時兩類參數；各參數代碼、型別、允許範圍及核准值由平台政策定義。
2. 系統參數變更須受 M04 權限檢查；各參數可由哪些管理者角色修改，依核准權限矩陣落實。
3. 設定變更只影響變更後新建立的活動或 Session，不回溯修改已建立的活動設定或既有 Session 狀態。
4. 參數批次更新的原子性、參數相依驗證及併發衝突處理未由來源指定，需由平台 API／資料一致性契約核定。
5. Session 逾時由 M01 定義登入 Session 語意及安全政策；M10 可調值範圍依平台政策核定，變更供新建立的 Session 使用。

### 4.2 稽核事件

1. 核心安全敏感異動須可追溯，且在 M10 查詢 UI 上線前已由來源模組產生必要事件；M01 提供成功登入／登出事件，M03 提供老師帳號異動事件，M04 提供角色功能授權異動事件。
2. 登入稽核只記錄成功登入及登出，不記錄失敗登入事件；失敗登入仍依 M01 安全政策處理，不得由 M10 稽核查詢洩露帳號狀態。
3. 基本追溯欄位為事件類別、伺服器事件時間、操作者、目標及操作結果；欄位不適用時依事件契約表示，不得以認證秘密補值。
4. 查詢條件、排序、分頁、查詢上限、時間時區及保存／匿名化期限由平台資料治理政策核定。
5. 稽核紀錄防竄改、匯出及法律保全需求另由安全／法務審查，不列為本版 M10 驗收門檻。

### 4.3 活動監控

1. 活動監控僅限系統管理者查詢，提供活動識別／狀態及彙總連線摘要；不提供個別參與者連線明細。
2. 監控以查詢為主，不包含主動告警；監控狀態過期或無法取得時標示「未知」，有資料時顯示最後更新時間。
3. 連線狀態定義、刷新週期及新鮮度門檻由 M08／平台共通 NFR 契約核定；本規格不指定數值。
4. 活動操作權仍由 M07 主持老師掌握，M10 監控不提供活動控制功能。
5. 監控資料不呈現學員個別身分或作答內容，只提供約定的活動與彙總連線摘要。

## 6. 資料、欄位與邊界規則

- **系統參數：** M10-01 範圍為活動預設值及 Session 逾時；具體值、型別及允許範圍由平台政策核定。設定只套用於新建活動／Session，不回溯改寫既有項目。
- **Session 逾時：** M01 定義逾時語意與安全政策；M10 可調範圍依平台政策核定，更新僅作用於新建立的 Session。
- **稽核事件欄位：** 最低欄位為事件類別、伺服器事件時間、操作者、目標及操作結果。不得記錄密碼、Token、Session 識別秘密或重設憑證。
- **登入事件：** 只記錄成功登入與登出，不記錄失敗登入事件；失敗登入防護依 M01 安全政策處理。
- **時間與查詢：** 查詢條件、時區、排序、分頁、保留期限與匿名化期限由平台資料治理政策核定；本規格不訂定數值。
- **活動監控：** 僅管理者可查活動及彙總連線摘要，不提供個別參與者連線明細；過期或不可得時標示「未知」，可得時附最後更新時間；刷新週期及新鮮度門檻由平台契約核定。
- **告警與防竄改：** M10 活動監控以查詢為主，不含告警。稽核防竄改、匯出及法律保全另列安全／法務審查，不屬本版驗收範圍。
- **核心事件先行性：** M01／M03／M04 的核心安全敏感異動須在 M10 查詢 UI 上線前可追溯；來源模組各自產生必要事件。
- **待確認事項：** (1) 活動預設值及 Session 逾時的核准值、型別及上下限為何？(2) 各類稽核事件欄位的個案適用規則及操作者／目標識別格式為何？(3) 平台資料治理政策所定查詢條件、時區、排序、分頁與保存／匿名化期限為何？(4) 安全／法務審查對防竄改、匯出及法律保全的決定為何？(5) 活動連線狀態定義、刷新週期及新鮮度門檻為何？(6) M03 的老師啟用事件是否一併納入稽核紀錄？

## 7. 非功能性需求

- **安全授權：** 每個 M10 查詢與寫入請求均須由後端驗證帳號狀態與功能權限；活動監控限系統管理者。驗證依賴不可用時採拒絕存取，不得 fail-open。
- **設定完整性：** 新設定僅供後續新建活動／Session 使用，不回溯改寫既有設定；可調值範圍與型別依平台政策驗證。批次原子性及併發策略由平台 API 契約核定。
- **稽核可追溯性：** M01／M03／M04 核心安全敏感事件須於 M10 查詢 UI 上線前即可追溯；事件與狀態一致性契約由來源模組定義。防竄改等加強控制另案安全審查。
- **隱私與資料最小化：** 稽核事件採核定的基本追溯欄位，不記錄認證秘密；活動監控限活動與彙總連線摘要，不顯示個別連線明細。
- **服務狀態可信度：** 活動連線資料過期或不可得時標示「未知」，可得時顯示最後更新時間；刷新週期與新鮮度門檻由 M08／平台契約核定。
- **效能與可用性：** 稽核查詢範圍、分頁、監控刷新頻率及服務目標依平台共通 NFR 確認；監控提供查詢，不含主動告警。
- **保存與清除：** 稽核／監控資料的保留期限、刪除或匿名化方式依核准資料治理政策決定。

## 9. 跨模組契約事項

- **M03 老師維護與管理：** M10-04 記錄老師建立、修改、停用；啟用事件依 M03 生命週期事件納入。核心帳號異動須在 M10 查詢 UI 上線前可追溯。
- **M04 角色與功能對應管理：** 提供角色功能授權異動事件；核心權限異動須在 M10 查詢 UI 上線前可追溯。M10 查詢權限依系統管理者權限矩陣控管。
- **M06 教學活動管理：** 提供活動建立所用的預設值；M10 預設值變更僅影響新建活動，不回溯修改既有活動設定或歷史快照。
- **M07 老師即時控制台：** 活動控制由主持老師負責；M10 活動監控不提供活動控制功能。
- **M08 學員互動管理／平台連線服務：** 提供活動彙總連線狀態及其更新時間；狀態過期或不可得時由 M10 顯示「未知」。刷新週期與新鮮度門檻依平台契約核定。
- **平台資料治理／NFR：** 定義稽核查詢條件、時間時區、分頁、保存／匿名化期限及監控刷新門檻；防竄改、匯出與法律保全另經安全／法務審查。
