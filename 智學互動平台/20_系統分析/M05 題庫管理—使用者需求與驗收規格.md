# M05 題庫管理—使用者需求與驗收規格

> **來源：**《即時互動教學系統 — 系統功能規劃書 V1.2》M05（題庫管理）及相關角色權限矩陣、資料模型與業務規則
> **模組優先級：** P0
> **規格狀態：** 依來源規劃書整理；跨題庫可見範圍、題型欄位規則、題庫／題目刪除及使用後維護政策待確認。

## 1. 需求概覽與假設

- **功能目標：** 讓老師建立、維護、分類、搜尋及複製可重用的題庫，並以受控的題型與答案內容支援後續教學活動。
- **範圍：** 涵蓋 M05-01～M05-06：建立題庫、維護題目及答案、管理單選／多選／投票／開放式文字題型、複製題庫、分類及搜尋／檢視題庫。
- **操作者與權限：** 預設由具備 M04 所定 M05 權限的老師操作；老師只能維護自己擁有的題庫。`SYSTEM_ADMIN` 不因管理者角色自動取得老師功能；若同時具備 `TEACHER` 角色，仍須滿足 M04 權限及資源擁有者檢查。所有限制由後端執行，不能只依賴前端隱藏操作。
- **可見範圍假設：** 本規格先以老師自己的題庫作為可搜尋及檢視範圍。規劃書另提「可用題庫」及複製現有題庫，但未定義跨老師或跨組織共享政策；在該政策確認前，不推定老師可瀏覽或複製其他老師的題庫。
- **資料與活動關聯：** 題庫由帳號擁有，題庫包含題目；M06 可選用題庫建立活動。活動應保留當時使用題目的快照，避免來源題庫後續編輯改變歷史活動題目與結果。
- **不在本規格自行決定：** 欄位長度、選項數及答案格式、分類／標籤管理方式、複製欄位範圍、使用後編輯／刪除策略、跨擁有者可見性與分享方式，均依本文待確認事項處理，不以假設作為核定產品規則。

## 2. 功能範圍

| 功能 ID | 功能名稱 | 功能說明 | 範圍界線 |
|---|---|---|---|
| M05-01 | 建立題庫 | 建立題庫並設定名稱、主題及描述。 | 欄位必填性、格式與長度待確認；須建立擁有者關聯。 |
| M05-02 | 維護題目 | 新增、修改及刪除題目與答案。 | 題目／答案欄位規則及題庫已被活動引用時的處理方式待確認；不得改變既有活動快照。 |
| M05-03 | 題型管理 | 支援單選、多選、投票及開放式文字題型。 | 各題型的選項、正解、計分及文字限制未由 M05 定義；計分依活動及相關模組契約。 |
| M05-04 | 題庫複製 | 複製既有題庫供其他課程使用。 | 可複製來源範圍、複製欄位、歸屬及複製後名稱規則待確認。 |
| M05-05 | 題庫分類 | 依課程主題或標籤分類。 | 主題與標籤是自由輸入或共用分類、可否多重分類及管理權限待確認。 |
| M05-06 | 題庫查詢 | 搜尋及檢視老師自己的題庫。 | 搜尋欄位、篩選、排序、分頁及「可用題庫」的跨擁有者含義待確認。 |

## 3. 使用者故事

> **身為**具備 M05 功能權限的老師，
> **我希望**建立並維護自己的題庫與題目，依課程主題或標籤整理、搜尋及複製題庫，
> **以便於**在不同課程與教學活動中重複使用教材，並維持活動歷史內容的一致性。

## 4. 驗收條件

```gherkin
Feature: M05 題庫管理

  Background:
    Given 操作者已登入且帳號為啟用狀態
    And 操作者具備 M04 授權矩陣所定的 M05 對應功能權限
    And 所有讀寫操作均由後端驗證資源擁有者及允許的操作範圍

  Scenario: 建立題庫
    Given 老師提供題庫名稱、主題及描述
    And 欄位符合已核定的 M05 欄位規則
    When 老師建立題庫
    Then 系統建立題庫並關聯至該老師帳號
    And 老師可在自己的題庫清單中檢視該題庫
    And 系統不得將題庫建立為無擁有者資料

  Scenario: 建立題庫欄位不符合規則
    Given 老師提交缺少必填欄位或格式不符的題庫資料
    When 老師建立題庫
    Then 系統拒絕建立並指出可修正的欄位
    And 不留下部分題庫資料
    And 具體必填及格式規則依已核定的欄位契約驗證

  Scenario: 維護自己的題目及答案
    Given 題庫屬於目前老師且老師具備 M05 寫入權限
    When 老師新增、修改或刪除題目及其答案
    Then 系統只在該題庫範圍執行所要求的變更
    And 成功後題庫內容反映該變更
    And 題型及答案符合其已核定的題型規則

  Scenario: 支援規劃書列出的題型
    Given 老師正在建立或編輯題目
    When 老師將題目設為單選、多選、投票或開放式文字
    Then 系統將題目保存為所選題型
    And 後續讀取時可辨識題型及其符合該題型契約的內容
    And 系統不得自行將題型轉為其他題型或推定未核定的答案／計分規則

  Scenario: 題目內容違反其題型規則
    Given 老師提交的題目或答案不符合已核定的該題型欄位規則
    When 老師保存題目
    Then 系統拒絕該題目變更並指出可修正欄位
    And 原有題目內容保持不變
    And 系統不以未核定的選項數、字數或正解規則判斷有效性

  Scenario: 複製可複製範圍內的題庫
    Given 老師有權檢視及複製指定來源題庫
    When 老師要求複製題庫
    Then 系統依核定的複製範圍建立新的題庫資料
    And 新題庫歸屬於執行複製的老師
    And 修改新題庫不會改動來源題庫
    And 複製欄位及預設名稱依已核定的複製契約處理

  Scenario: 依主題或標籤分類題庫
    Given 題庫屬於目前老師且老師具備 M05 寫入權限
    When 老師為題庫設定或修改課程主題／標籤
    Then 系統保存符合已核定分類規則的分類資訊
    And 分類結果可供題庫查詢及檢視
    And 分類設定不得改變題庫擁有者或題目內容

  Scenario: 搜尋及檢視自己的題庫
    Given 老師擁有一個或多個題庫且具備 M05 讀取權限
    When 老師搜尋或檢視自己的題庫
    Then 系統只回傳該老師有權檢視的題庫及其允許檢視的題目內容
    And 搜尋條件及結果不得擴大老師的資源存取範圍

  Scenario: 沒有符合條件的題庫
    Given 老師的可見題庫中沒有符合搜尋條件的資料
    When 老師執行搜尋
    Then 系統回傳空結果
    And 不建立或修改題庫資料

  Scenario: 未授權使用者不得存取題庫
    Given 使用者未登入、帳號已停用或不具備所需 M04 權限
    When 使用者查詢、建立、編輯、刪除、分類或複製題庫／題目
    Then 後端拒絕該要求
    And 不回傳非授權資料或執行異動
    And 前端隱藏功能不得取代後端授權檢查

  Scenario: 老師不得維護其他老師的私人題庫
    Given 指定題庫不屬於目前老師且未有經核准的共享／複製授權
    When 老師嘗試檢視或維護該題庫
    Then 系統依資源授權規則拒絕該操作
    And 不回傳該題庫內容或留下任何異動

  Scenario: 建立活動快照後修改來源題庫
    Given M06 活動已建立包含題庫題目的 SESSION_QUESTION 快照
    When 老師修改來源題庫中的題目或答案
    Then 已建立的活動快照及該活動歷史結果保持不變
    And 後續新建活動才可依 M06 流程選用更新後的題庫內容

  Scenario: 活動引用中的題目要求刪除或修改
    Given 題目已被一場或多場活動引用
    When 老師要求修改或刪除該題目
    Then 系統依已核定的題庫生命週期及活動引用政策處理
    And 無論來源題庫如何變更，既有活動快照及歷史結果均不得被改寫

  Scenario: 並行修改同一題庫內容
    Given 兩個有效請求同時修改同一題庫或題目
    When 系統提交兩項修改
    Then 系統依已核定的平台併發控制契約處理衝突
    And 不得產生部分寫入或靜默破壞既有題目資料
    And 衝突處理策略及回應格式依平台共通契約

  Scenario: 必要服務暫時不可用
    Given 權限、題庫儲存或其他必要依賴無法完成驗證或寫入
    When 老師提出題庫或題目查詢／異動要求
    Then 系統不得將未完成操作視為成功
    And 寫入失敗不得留下不一致的部分資料
    And 系統依平台錯誤契約回覆可重試的服務錯誤且不洩露內部資訊
```

## 5. 資料、欄位與邊界規則

- **題庫資料：** 來源明定題庫名稱、主題及描述，並以 `USER_ACCOUNT` 擁有 `QUESTION_SET`、`QUESTION_SET` 包含 `QUESTION`。各欄位必填性、型別、長度、空白正規化及唯一性均待確認；不可在未核定前假設題庫名稱全域唯一或特定字數限制。
- **題目與答案：** 題型至少包含單選、多選、投票及開放式文字。題幹、選項、正解、允許多個正解、投票選項、文字回答限制及各題型必填欄位待確認。題庫管理不自行決定活動計分；投票／文字不計分等規則依 M11／活動規格，適用時不得由 M05 推廣成未核定的題庫限制。
- **擁有權與可見範圍：** 老師只能維護自己擁有的題庫（BR-002）；查詢及明細須執行資源層級授權。規劃書矩陣所稱「可用題庫」及複製「現有題庫」的跨老師、跨組織範圍待確認。在政策確認前，API 不得因搜尋或複製功能而默認授予跨擁有者存取。
- **複製：** 複製結果應是新的題庫且修改不回寫來源，避免破壞「供其他課程使用」的重用目的；複製題目、答案、分類、描述、來源標記、命名方式及來源權限均待確認。跨擁有者複製前須先定義來源可見及授權規則。
- **分類與搜尋：** 來源僅規定依課程主題或標籤分類並搜尋／檢視題庫；主題與標籤的資料模型、是否可多選、共享／私有範圍、搜尋欄位、排序、分頁及篩選待確認。查詢不得繞過擁有者檢查。
- **刪除與使用後維護：** M05-02 包含刪除題目、規劃總覽亦列題庫刪除，但未定義軟／硬刪除、封存／復原或被活動引用時的處理。須確認後才定義精確行為；任何處置均須維持既有活動快照、歷史結果及必要關聯。老師帳號停用不會刪除其歷史題庫或教學紀錄。
- **活動快照：** M06 活動可選用題庫；規劃書建議以 `SESSION_QUESTION` 保存題目快照，避免活動後修改原始題庫影響歷史結果。快照需保留供活動結果解讀所需的題目內容；具體欄位及何時建立由 M06 契約定義。
- **稽核：** 題庫／題目建立、編輯、刪除、複製及分類是否記錄、欄位、失敗事件與保存期限依 M10 全域稽核政策確認；不得記錄認證秘密或非必要敏感資料。

## 6. 非功能性需求

- **授權安全：** 所有 M05 API 均須由後端驗證登入狀態、帳號有效狀態、M04 對應功能權限及題庫資源擁有者／明確授權範圍。前端顯示控制不是安全邊界；無法完成授權驗證時不得允許操作。
- **資料完整性：** 題庫與題目關聯須一致；新增、修改、刪除及複製不得留下半完成資料。題庫擁有者關聯不可因題庫修改或複製而被意外變更。
- **歷史一致性：** 題庫來源後續修改不得回溯改變已建立活動的題目快照、作答解讀或歷史結果；快照及保留策略由 M06／平台資料政策具體化。
- **隱私：** 搜尋、檢視及複製只可處理操作者已獲授權的題庫內容；跨老師或組織共享不得由 M05 功能名稱推定為已授權。
- **可稽核性：** 題庫重要異動依 M10 政策可追查操作者、時間、目標及結果；保存期限及欄位沿用全域政策，不另行假設。
- **可用性與效能：** 題庫搜尋、讀取及儲存的回應時間、容量、分頁和併發策略沿用平台整體 NFR；本模組不設定未核定的數值門檻。

| 編號 | 待確認項目 | 需決策內容／影響範圍 |
|---|---|---|
| Q01 | 題庫可見範圍 | M05-06 的「自己的題庫」與 M04 矩陣的「可用題庫」如何一致？老師是否可檢視其他老師或組織的題庫？如可，授權／分享及撤銷方式為何？ |
| Q02 | 題庫與題目欄位 | 名稱、主題、描述、題幹、選項、答案欄位的型別、必填性、格式、長度及正規化規則為何？ |
| Q03 | 各題型規則 | 單選／多選的選項數、正解表示與多正解規則為何？投票是否有選項？開放式文字是否有標準答案或字數限制？ |
| Q04 | 題庫複製語意 | 可複製哪些來源題庫及欄位？複製題目、答案、分類與描述嗎？複製品是否獨立？如何命名及標註來源？跨老師複製是否允許？ |
| Q05 | 分類與標籤 | 主題及標籤是自由輸入或受管理分類？是否可有多個標籤？標籤是個人、課程或全平台共用？是否提供獨立管理功能？ |
| Q06 | 搜尋能力 | 支援哪些搜尋欄位、精確／部分比對、篩選、排序及分頁？空搜尋如何處理？「可用題庫」搜尋是否包含經共享的題庫？ |
| Q07 | 編輯／刪除及引用限制 | 已被活動選用或已產生快照的題庫／題目可否編輯、刪除？刪除是軟刪除、封存或實體刪除？既有活動與未開始活動如何處理？ |
| Q08 | 題庫刪除功能邊界 | 系統架構總覽列出題庫刪除，但 M05 詳細清單僅明列題目刪除；是否提供題庫刪除及其權限、限制與復原方式？ |
| Q09 | 權限代碼及資源範圍 | M05-01～06 各動作如何映射至 M04 的 `M05_READ`／`M05_WRITE`，尤其複製及跨擁有者檢視／複製？資源範圍如何表達？ |
| Q10 | 稽核與併發 | M05 各異動的稽核欄位、失敗操作記錄及保存期限沿用何種 M10 決策？題庫並行修改採何種衝突偵測及回應方式？ |

## 8. 跨模組契約事項

- **M01 帳號與登入：** 提供已登入使用者身分及帳號有效狀態；停用帳號不得繼續呼叫 M05 受保護功能。
- **M02 角色管理：** 提供有效角色狀態；`SYSTEM_ADMIN` 不自動代表老師權限，角色停用的即時撤權依 M02／M01 契約。
- **M03 老師維護：** 老師帳號停用不刪除其歷史題庫或教學紀錄；題庫保留及擁有者關聯須支援歷史追溯。
- **M04 角色與功能對應：** 為 M05 查詢、建立、維護、刪除、複製及分類定義模組讀取／寫入權限映射；每個後端 API 除功能權限外均須檢查題庫擁有者或明確授權範圍。M04 權限目錄未核准跨擁有者共享前，不得由角色權限推定資源可見。
- **M06 教學活動管理：** 提供題庫選用及題目快照契約，明確定義活動建立／開始時快照的時點、內容與後續來源題庫變更隔離方式。M05 不得改寫既有 `SESSION_QUESTION` 快照。
- **M07／M08／M09／M11：** 題型呈現、作答、統計及計分依活動互動與分析模組契約；M05 僅保存題庫題型內容，不自行定義活動狀態、公布流程或額外計分政策。
- **M10 系統設定與稽核：** 題庫及題目異動的稽核事件欄位、成功／失敗範圍、遮罩及保存期限依 M10 全域政策。
- **平台共通契約：** 錯誤回應、搜尋／分頁、併發控制、交易原子性、效能及依賴不可用時的處理遵循平台共通規格；必要依賴無法驗證時不得 fail-open。

## 9. 來源規則與關聯

- **M05 原始功能清單：** M05-01～M05-06 題庫建立、題目及答案維護、題型、複製、分類、查詢，來源規劃書第 328–337 行。
- **模組優先級與角色矩陣：** M05 為 P0；老師建立／編輯自己的題庫及搜尋／檢視可用題庫，來源規劃書第 41–53、296–322 行。
- **資料模型：** `USER_ACCOUNT` 擁有 `QUESTION_SET`，`QUESTION_SET` 包含 `QUESTION`；活動透過 `SESSION_QUESTION` 關聯並保存題目快照，來源規劃書第 590–635 行。
- **業務規則：** BR-002（老師只可維護自己擁有的題庫及教學活動）、BR-005（前端與後端均須落實權限檢查），來源規劃書第 645–654 行。
- **帳號停用與資料保留：** 老師停用不代表刪除歷史題庫或教學紀錄，來源規劃書第 241–251 行。
- **相關模組規格：** M01 帳號與登入；M02 角色管理；M03 老師維護與管理；M04 角色與功能對應管理；M06 教學活動管理；M07 老師即時控制台；M08 學員互動管理；M09 即時統計與結果分析；M10 系統設定與稽核；M11 可選分組與團隊競賽。
