# US-F0 CP5 — 收尾執行計畫（spec 修正 + baseline + 重跑）2026-08-24

## Context

US-F0 CP5（真實 backend／Playwright Course flow 驗收）的 spec 已存在且 static 通過，但 **real-browser acceptance 仍 BLOCKED**（`smartLearning-ui` commit `d478258` 已記錄）。上一次 live run（見 `US-F0 CP5 執行-2026-08-24.md`）的失敗**並非產品/backend 缺陷，而是 spec 斷言 bug**：

- `assertMutationHeaders`（`smartLearning-ui/test/browser/us-f0-course-flow.spec.ts:355`）用 `request.headers()` 讀 `Origin`。Playwright 在**跨源請求**下 `headers()` **不含 `origin` key** → `headers.origin === undefined` → `undefined !== uiOrigin` 誤判為「未送出正確 Origin」，測試失敗。
- 瀏覽器實際有送出 `Origin`（`request.allHeaders()` 與 HAR trace 都證明），`x-csrf-token` 在 `headers()` 與 `allHeaders()` 都在，**只有 `Origin` 只出現在 `allHeaders()`**。

目標：修正 spec → 重新 baseline 隔離 fixture → 對真實 backend 重跑 live Playwright 得到 **PASS** → 更新 CP-E acceptance matrix 並提交。依既有 repo 慣例，**以 checkpoint 切分，每個 checkpoint 邊界由使用者手動確認後才進入下一步**。

既有 `smartLearning-ui/tasks/lessons.md` 已含 `headers()`/`allHeaders()` 教訓，無需重寫。

### CP-A — Spec 修正 + static 驗證（low risk，不改產品/backend）

**修正 `smartLearning-ui/test/browser/us-f0-course-flow.spec.ts`：**
- `assertMutationHeaders` 改為 `async`，改用 `await request.allHeaders()`：
  ```ts
  async function assertMutationHeaders(
    request: Request,
    expectedCsrf: string,
    label: string,
  ) {
    const headers = await request.allHeaders();
    if (headers.origin !== uiOrigin) {
      throw new Error(`${label} did not send the exact UI Origin`);
    }
    const csrf = headers["x-csrf-token"];
    if (typeof csrf !== "string" || csrf.length === 0) {
      throw new Error(`${label} did not send a non-empty lowercase x-csrf-token header`);
    }
    if (csrf !== expectedCsrf) {
      throw new Error(`${label} did not echo the context CSRF cookie`);
    }
  }
  ```
  （`allHeaders()` 回 `Promise<Record<string,string>>` 且 key 全小寫，故 `headers.origin` / `headers["x-csrf-token"]` 保持相同寫法。）
- 3 個 call site 加 `await`：line 487、744、961。

## 風險與 Rollback

- **Risk**: low（CP-A 只改 spec）、medium（CP-C 對隔離 backend 做 authenticated mutation）。
- **Rollback**: `git revert` 只撤 spec 修正與 task-log 變更；不 reset working tree、不動 backend/產品 code、不刪 runtime/domain data。隔離 fixture 可隨時重建（CP-C 是獨立 compose project）。
- **Scope guard**: 不新增產品功能、不改 backend/transport/依賴、不碰 F1/F9、不刪 `/tmp/us-f0-cp5-fixture.env`（除非另獲授權）。

- CP-A：typecheck / lint / prettier / diff-check（static）。
- CP-C：live Playwright run 全綠 = 最終驗收證據。
- CP-D：`git diff --check` + status/name-only scope review。
