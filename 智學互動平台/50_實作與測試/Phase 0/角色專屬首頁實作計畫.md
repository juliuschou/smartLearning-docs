# 角色專屬首頁實作計畫

## Context

目前登入後的角色導向不完整：student 已有 `/student` 與「我的課程」頁面，但 admin 的預設 `/admin` 沒有實際 route，teacher 沒有專屬 route/layout，teacher 會落到仍是 starter 內容的 `/`。結果是登入成功後可能進入不存在頁面或沒有角色辨識的首頁。

本計畫只針對目前 UI repository 與本計畫列出的需求執行，不引入其他文件的額外需求。目標是建立可驗證的角色 landing page，而不是提前實作尚不存在 API 支援的完整課程管理或 dashboard 統計。

## Scope and acceptance criteria

- [ ] admin 登入的預設目的地 `/admin` 有可存取的角色首頁，並能前往既有 `/admin/accounts/new`。
- [ ] student 保留 `/student` 現有「我的課程」功能，並納入一致的角色首頁導向與 shell 行為；不新增虛構課程資料或 enrollment API。
- [ ] teacher 新增受保護的 `/teacher` route、teacher layout 與 landing view。
- [ ] teacher landing 只顯示真實 `SessionDto` 可證明的資訊：displayName、username、角色、`canCreateCourse`；不顯示假課程、假統計或尚未存在的 API 結果。
- [ ] 正常登入無 `next` 時導向：admin `/admin`、student `/student`、teacher `/teacher`。
- [ ] `mustChangePassword=true` 仍優先導向 `/settings/password`，不受 `next` 或角色首頁影響；變更成功後 teacher 導向 `/teacher`。
- [ ] 未登入或錯誤角色不能看到角色首頁，會以編碼後的 `next` 導向 `/login`；既有 open-redirect 防護不退化。
- [ ] admin/student/teacher 首頁均可使用既有變更密碼與登出流程。
- [ ] 不新增 backend endpoint、資料 schema、mock/placeholder API 資料或新依賴。

## Recommended design

採用最小垂直切片：新增缺少的 role route，沿用現有 route-group layout 與 `useSession()` guard；不在本次抽出共用 shell，也不改 public root `/` 的用途。這可修正實際 404／teacher fallback，同時避免重構三個已有 layout 造成額外風險。

### 1. Admin landing

新增 `app/(admin)/admin/page.tsx`，使用現有 admin layout 保護，提供：

- admin 主控台標題與簡短說明。
- 明確的 `Link` 前往 `/admin/accounts/new`。
- 不新增帳號列表、統計或其他 API；現有建立帳號頁保持不變。

視需要在 `app/(admin)/layout.tsx` 的 header 加入「建立帳號」連結，確保既有 admin 功能可從 shell 到達；若頁面 CTA 已足夠，避免重複導航。

### 2. Student landing

保留 `app/(student)/student/page.tsx` 與 `features/student/MyCoursesView.tsx` 作為 student landing 的資料內容，僅做角色首頁契約所需的最小調整：

- 不改 `useMyCourses()` 的 student-only query gate、loading/error/empty/data 四態。
- 若需要共用首頁文案或導航，沿用現有 student layout 與 `LogoutButton`，不新增課程功能。
- 將 student 的預設 route 明確納入 role-home mapping 與回歸測試。

### 3. Teacher landing

新增：

- `app/(teacher)/layout.tsx`：複製既有 admin/student layout 的必要 guard 行為，但角色限定為 `teacher`。
  - loading 顯示既有 placeholder。
  - `mustChangePassword` 優先 redirect `/settings/password`。
  - 未登入或錯誤角色 redirect `/login?next=<encoded pathname>`。
  - 成功時顯示 teacher shell、變更密碼連結與既有 `LogoutButton`。
- `app/(teacher)/teacher/page.tsx`：server page shell 與 metadata。
- `features/teacher/TeacherHomeView.tsx`：client view，透過 `useSession()` 顯示：
  - 個人歡迎訊息（`displayName`）。
  - 帳號名稱（`username`）。
  - 角色標示。
  - `canCreateCourse=true/false` 的清楚權限狀態。

teacher view 不呼叫 `apiRequest`，因此不需新增 query key、hook 或 API type。

### 4. Role-based redirect contract

在 `features/auth/LoginForm.tsx`：

- 保留現有單斜線相對 `next` 驗證與 `mustChangePassword` 優先規則。
- 將 teacher fallback 從 `/` 改為 `/teacher`。
- 保留 admin `/admin`、student `/student` fallback。

在 `features/auth/ChangePasswordForm.tsx`：

- 將 force-change 成功後的 teacher `roleHome` 從 `/` 改為 `/teacher`。
- 不改 voluntary change 的留頁行為。

不把 `/` 改成依 session dispatch 的角色入口；它維持 public starter route，避免本次變更影響未登入訪客與既有 URL。

## Implementation checkpoints

### Checkpoint A — route and behavior contract

- 確認新增 route 的檔案位置與 App Router route group nesting。
- 先補 redirect regression tests，使 teacher fallback 與 force-change 行為可被測試。
- 確認 admin `/admin`、student `/student`、teacher `/teacher` 三個 canonical home path。

### Checkpoint B — minimal implementation

- 新增 admin page、teacher layout/page/view。
- 修改兩個 role-home mapping。
- 只使用 session fields；不加入尚未存在 API 的課程管理入口或假資料。
- 保持既有 student query 與 auth mutation 行為不變。

### Checkpoint C — regression coverage

- Teacher view：`canCreateCourse=true` 與 `false` 兩種狀態、displayName/username/role 顯示、未呼叫 API。
- Teacher layout：loading、未登入、錯誤角色、must-change 優先、teacher 正常 render、encoded `next`。
- Admin landing：頁面標題與 `/admin/accounts/new` link。
- Login/change-password：teacher default 與 force-change redirect；既有 same-origin `next`、`//`/absolute URL open-redirect 防護保持通過。

### Checkpoint D — verification and delivery notes

- 執行 `npx next typegen`。
- 執行 `npm test`。
- 執行 `npm run typecheck`。
- 執行 `npm run lint:check`。
- 執行 `npm run build`。
- 執行 `git diff --check`。
- 若 backend 與測試帳號環境可用，再執行瀏覽器 smoke；目前 `test/browser` 沒有既有 spec，不能把未建立的 browser suite 當成已驗證成果。

## Risk and rollback

- **Risk level：中**：涉及登入後導向、角色 authorization shell 與 force-change redirect，但不涉及資料庫或 backend contract。
- **主要風險**：teacher layout gate 與既有 layout 行為不一致；錯誤角色可能看到 children；登入後 fallback 指向錯誤 route。
- **防護**：以既有 admin/student gate 順序實作，補 loading、unauthenticated、wrong-role、must-change regression tests，並保留 `next` open-redirect 驗證。
- **Rollback**：刪除新增 admin/teacher route/view/test，還原 `LoginForm` 與 `ChangePasswordForm` 的兩個 fallback 修改；不需 migration 或資料補償。

## Explicit non-goals

- 不實作 teacher 課程 CRUD、課程列表、課程統計、live session、enrollment 或任何新 API。
- 不重建 student 課程資料層；現有 `/me/courses` 行為維持不變。
- 不把 root `/` 改成 authenticated role dispatcher。
- 不抽出共用 AppShell/role guard；若三個 layout 的重複未阻礙本次需求，留作後續獨立重構。
- 不建立或執行不存在的 Playwright browser spec 作為本次必要範圍。
