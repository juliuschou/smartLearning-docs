## Outcome — 2026-08-24 (CP-D executed; real-browser acceptance BLOCKED by a spec bug)

### CP-D result — FAIL (not a skip), root cause isolated

Executed the live run `node test/browser/run.mjs --workers=1 test/browser/us-f0-course-flow.spec.ts` with the 8 `F0_*` fixtures sourced. Result: **1 failed** (fail-closed gate held; never `test.skip`).

- **Failure point**: `Enable teacher course permission did not send the exact UI Origin` at `assertMutationHeaders` (`us-f0-course-flow.spec.ts:357`). Cleanup also reported `restore original teacher permission, teacher logout`.
- **Root cause (confirmed, not a backend/UI defect)**: the browser **does** send `Origin: http://localhost:3001` + non-empty `X-CSRF-Token` on the PATCH (proven via HAR trace and `request.allHeaders()` returning `origin: "http://localhost:3001"`). But the spec reads `request.headers()`, and on a real cross-origin request Playwright's `headers()` **omits the `Origin` key** → `headers.origin` is `undefined`, so `undefined !== "http://localhost:3001"` throws a false-negative. The `x-csrf-token` key *is* present in `headers()`, so only the Origin check breaks. Fix: use `request.allHeaders()`.
- **Fixture side-effect during diagnosis**: `cp5teacher.can_create_course` was toggled to `true` during isolated diagnostic runs; a restore attempt was declined at the permission gate. **The fixture is not at CP-C baseline** (`can_create_course=true`, `courses=0`). Must re-baseline to `false` before any rerun.
